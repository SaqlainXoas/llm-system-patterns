# Contributing

![Badge](https://img.shields.io/badge/Contributions-Welcome-0ea5e9) ![Badge](https://img.shields.io/badge/Docs-Markdown--first-0f172a?logo=markdown&logoColor=fff)

## Quick rules
- Keep PRs small and focused.
- Prefer one main idea per PR.
- Keep docs skimmable, practical, and linked to related patterns or examples.

## What we accept
- New pattern docs in `patterns/`.
- New decision guides in `decision-guides/`.
- Small example improvements in `examples/`.
- Clarity fixes, diagrams, and code simplifications that improve teaching value.

## Style guidance
- Prefer plain Python over framework-heavy abstractions.
- Keep file counts small unless a split clearly teaches a separate stage.
- Use simple names and readable top-to-bottom flow.
- Add comments only when they explain a real stage or tradeoff.
